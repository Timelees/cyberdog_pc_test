# 数据格式定义

## 命名空间设置

以 `cyberdog_1`～`cyberdog_10` 作为 10 台机器的命名空间，用作 ROS 话题区分：

- A 队：`cyberdog_1`～`cyberdog_5`，当前仿真前锋固定为 `cyberdog_1`；
- B 队：`cyberdog_6`～`cyberdog_10`。

## 重要ros2话题

**PS:** 订阅或发布话题时记得加上命名空间

控制驱动话题：/motion_servo_cmd

位置信息话题：

- **/{namespace}/odom_out:** 惯性里程计输出话题

- **/{namespace}/odom_slam:** 视觉惯性里程计（VIO）输出话题

- **/{namespace}/odom_global:** 单机VIO经过坐标系统一后的输出话题【需要在cyberdog端启动功能包[apriltag_ros](./src/apriltag_ros)中的[apriltag识别](../src/apriltag_ros/launch/apriltag_36h11.launch.py)和[VIO里程计坐标转换](../src/apriltag_ros/launch/odom_transform.launch.py)进行转换】

- **/global_vio/{namespace}/odom:** 多机VIO数据统一到同一坐标系下的位姿话题【由功能包[mutil_robot_odom](../src/mutil_robot_odom/launch/global_vio_odom.launch.py)转换】

足球导航的规划避障、角色分配和可视化均直接订阅上述 10 路独立
`nav_msgs/msg/Odometry`。不再使用 `/<robot>/football/other_robot_poses`
聚合话题。单机仿真也发布相同接口，因此后续切换实机时无需修改下游话题协议。

机器人可视化话题为 `/football/markers/robots/{namespace}`。每一路
`visualization_msgs/msg/MarkerArray` 同时包含该机器人的碰撞矩形、轮廓和随动坐标文本。


# 数据格式

1. **文件路径**：机器人源码/bridges/protocol/ros

2. **消息格式**
    
    - **控制指令：** protocol::msg::MotionServoCmd
    
        数据发布参考[**键盘控制程序**](../src/keyboard_input/)实现
        
        ```
        int32        motion_id
        int32        cmd_type
        int32        cmd_source   
        int32        value
        float32[]    vel_des      # x y yaw speed  m/s
        float32[]    rpy_des      # roll pitch yaw  rad
        float32[]    pos_des      # x y z  m/s
        float32[]    acc_des      # acc for jump m^2/s
        float32[]    ctrl_point   # pose ctrl point  m
        float32[]    foot_pose    # front/back foot pose x,y,z  m
        float32[]    step_height  # step height when trot  m

        # cmd_type 取值定义
        int32 SERVO_START = 0
        int32 SERVO_DATA = 1
        int32 SERVO_END = 2

        # cmd_source 取值定义
        int32 APP = 0
        int32 AUDIO = 1
        int32 VIS = 2
        ```

        **motion_id定义：**/bridges/protocol/ros/msg/MotionID.msg
        
        motion_id仅需使用以下内容：

        ```
        int32 ESTOP = 0                 # 急停
        int32 GETDOWN = 101             # 趴下
        int32 RECOVERYSTAND = 111       # 站立
        int32 WALK_USERTROT = 303       # 慢走模式
        
        ```
        以及
        ```
        motion_id = 308                 # 快走模式
        位于路径：/motion/motion_action/preset/motion_id_map.toml
        ```

        **cmd_type字段内容：**
        
        ```
        int32 SERVO_START = 0
        int32 SERVO_DATA = 1
        int32 SERVO_END = 2
        ```

        使用时代码中填充

        ```
        protocol::msg::MotionServoCmd::SERVO_START
        protocol::msg::MotionServoCmd::SERVO_DATA
        protocol::msg::MotionServoCmd::SERVO_END
        ```

        cmd_source字段可使用protocol::msg::MotionServoCmd::APP

        value填2即可

        step_height固定为0.05即可

        由于场地为平地，所以使用vel_des，发送x y yaw速度即可，具体数值可根据**路径规划**部分计算的速度数据。

    - **里程计数据：** nav_msgs/msg/Odometry

        主要使用pose和orientation字段的数据，pose字段包括x,y,z位置信息，orientation字段为姿态四元数，需进行转换为欧拉角表示机器人朝向
